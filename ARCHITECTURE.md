# Архитектура: планировщик маршрутов развоза

## Задача
Вечером водитель получает список клиентов (ООО/ИП) на завтра. Нужно автоматически выставить порядок объезда, чтобы маршрут был самым быстрым и дешёвым, с учётом платных дорог, плохих дорог и весовых постов.

## Схема

```
Телефон водителя (PWA, Leaflet)
        │  вход / чтение / запись (RLS)            ┌──────────────┐
        ├──────────────────────────────────────────▶ Supabase      │ clients, hazards,
        │                                           │ Auth + Postgres│ trip_plans, trip_stops
        │  /api/optimize, /api/geocode              └──────▲───────┘
        ▼                                                  │ читает hazards с токеном водителя
Netlify Functions ─────────────────────────────────────────┘
        │  матрица времени/км, маршрут, геокодинг
        ▼
OpenRouteService (профиль driving-hgv, данные OSM)
```

Netlify и Supabase — только хостинг, база и вход. Тяжёлый расчёт маршрутов делает OpenRouteService; порядок точек — собственный решатель в `netlify/functions/lib/solver.js`.

## Как считается маршрут
1. **Матрица затрат** между всеми точками (склад + клиенты) для грузового профиля. Стоимость пары = `часы × ₽/час + км × ₽/км`. Так «быстрее» и «дешевле» сводятся к одному числу, а вес задаёт диспетчер.
2. **Порядок объезда**: до 12 точек — точный перебор (Хелд—Карп), больше — ближайший сосед + 2-opt + or-opt. Склад всегда первый, возврат на склад опционален.
3. **Построение дороги** по найденному порядку:
   - *плохие дороги* из таблицы `hazards` передаются как зоны, которые маршрут обходит (`avoid_polygons`);
   - *платные дороги*: считаются два варианта, с платными и без, выбирается дешевле по формуле выше; цена платных участков берётся из `hazards.toll_price_rub`;
   - масса и высота машины передаются как ограничения профиля.
4. **Весовые посты** сейчас не обходятся, а показываются предупреждением, если проезд проходит в радиусе от отметки.

## Откуда данные о дорогах
- Платные участки, ограничения по массе и высоте: из OpenStreetMap через OpenRouteService.
- Плохие дороги, весовые посты, цены проезда: своя база `hazards`, её пополняют водители прямо на карте, другие водители подтверждают кнопкой +1, диспетчер может удалять.

Это главный долгосрочный актив проекта: качество маршрутов растёт вместе с базой отметок.

## Ограничения MVP (честно)
- Покрытие OSM по платным участкам и ограничениям в России неполное, на первых порах цены и места платных дорог лучше завести вручную.
- Бесплатный тариф OpenRouteService имеет суточные лимиты и ограничение на 50 точек маршрута, у нас потолок 45 клиентов.
- Netlify Functions на бесплатном тарифе ограничены по времени (около 10 с). Для 30–45 точек обычно хватает; при превышении нужен фон (Background Functions) или свой сервер маршрутизации.
- Яндекс Карты открываются по готовому порядку точек, но навигатор может проложить путь иначе. Эталон — линия на карте приложения.
- Фоновый GPS, режим «еду по маршруту» и офлайн-карты в PWA ограничены; если понадобятся, это повод для нативного Android.

## Окна приёмки, ручной порядок, режим «Еду»
- Окна приёмки и время разгрузки входят в расчёт порядка: ранний приезд даёт ожидание, опоздание штрафуется. До 8 точек перебираются все варианты, дальше локальный поиск из нескольких стартов. Если окно невыполнимо, приложение показывает опоздание, а не прячет его.
- К времени в пути добавляется запас (по умолчанию 15%) на пробки и темп гружёной машины.
- Порядок можно менять перетаскиванием. Сервер пересчитывает время и километры и показывает разницу с расчётным порядком.
- Режим «Еду» показывает следующую точку, плановое прибытие, телефон и навигатор. Отметки «Готово» и «Пропустить» пишутся в `trip_stops`, рейс получает статус и время старта и финиша: это основа для будущего «план и факт».
- Быстрая отметка проблемы берёт GPS телефона. Если в радиусе 120 м уже есть такая отметка, она подтверждается вместо дубля.

## Этапы
1. **MVP (этот репозиторий)**: вход, клиенты, опасные точки, расчёт и карта, сохранение рейса.
2. Окна приёмки клиентов и время разгрузки в расчёте (VRP с time windows).
3. Весовые посты как штраф или объезд: перебор вариантов маршрута, кандидат с постом получает штраф.
4. Несколько машин и разбивка списка по водителям.
5. Отметки выполненных точек, факт vs план, статистика по расходам.
6. При росте нагрузки: свой Valhalla/GraphHopper на VPS вместо ORS.
